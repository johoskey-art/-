# 앵커 생성식 식별 v1 — 사전등록 검증

## 현재 확정된 범위

원본은 모두 로그가격축이라는 사용자 확인과, 삼성전기 동일 화면의 21개
가로 관측을 함께 쓰면 위치선의 **배치**는 다음 두 앵커 구조로 축약된다.

\[
B_b(t)=T(t)^{1-q_b}K(t)^{q_b}
\]

- \(T(t)\): 화면의 상투선 앵커
- \(K(t)\): 화면의 무릎선 앵커
- \(q_b\): 상투→무릎 로그거리에서 밴드 (b)의 상대 위치

이 결론은 `FORMULA_IDENTIFICATION_AUDIT_v2_20261020.md`의
폭 변화(+32.05%)와 내부 q 안정성으로 지지된다. 이것은 **배치식**이며,
앵커 \(T,K\)의 원작 생성식도, 실시간 예측식도 아니다.

## 이미 배제하거나 보류한 것

| 가설 | 상태 | 근거 |
|---|---|---|
| 240일선 × 고정비율 | 제외 | 사용자 지시로 폐기됐고 종목·구간 간 고정성 근거가 없다. |
| 고정 절대가격 수평선 | 반증 | 같은 화면에서도 전체 폭이 변한다. |
| 표준 Fibonacci q=(.236,.382,.618) | 낮은 적합 | 7화면 MAE 0.049886; 혼합 5/7 후보보다 현저히 크다. |
| MIXED_5_7_A/B가 원작식 | 보류 | 내부 상대배치 후보일 뿐 \(T,K\) 생성 규칙을 설명하지 못한다. |
| 사후 실제 고점 H를 실시간 상투선으로 입력 | 금지 | 미래정보 누수다. H는 평가 레이블로만 사용한다. |

## 다음 반증의 입력 원장

`data/anchor_observations_template_v1.csv`에는 각 원본 화면의 같은 날짜에
다음 값을 기록한다.

1. 화면 우측 두 실제 가격 눈금(또는 검증 가능한 차트 커서)으로 환산한
   상투선 \(T\), 무릎선 \(K\)의 원화값
2. 관측일과 이미지 식별자
3. 두 앵커의 정의와 미래정보 사용 여부
4. 5/7 역사 단계와 연결하려면, **차트값을 본 뒤 고르지 않은** 외부 상태 라벨

값이 비어 있으면 코드가 추정값을 만들지 않는다. 수집 코드는
`src/anchor_generator_validation.py`이며, 산출은 각 행의
\(\log(T/K)\)와 감사 상태다.

## 사전등록한 판정 순서

| 순서 | 질문 | 통과 기준 | 현재 상태 |
|---:|---|---|---|
| 1 | 같은 날짜의 T,K가 가격 단위로 재현되는가 | 두 실제 눈금/커서 근거와 일치 | 미측정 |
| 2 | 폭 (D(t)=\log(T/K)\)가 시간에 따라 변하는가 | 서로 다른 날짜의 D가 화면오차 이상으로 다름 | 화면기하상 지지, 가격값 미측정 |
| 3 | 5/7 통계가 D를 설명하는가 | 사전선언 상태 라벨 하나가 각 관측일 이전에 결정되고, 홀드아웃에서도 잔차가 유지 | 미검증 |
| 4 | 이동평균 등 특정 앵커 후보가 T,K를 설명하는가 | 기간·가격종류·기업행위 조정 규칙을 먼저 고정하고, 미사용 화면에서 오차 평가 | 미검증 |
| 5 | 원작식이라고 부를 수 있는가 | 1–4가 서로 다른 종목·날짜에서 재현되고 미래정보가 없음 | 아직 불가 |

## 왜 숫자 앵커가 필수인가

화면의 q만 알면 5개 선은 두 자유도 \(T,K\)로 표현된다. 임의의 앵커
경로에 대해 여러 Fibonacci 함수·이동평균·상태모형이 똑같은 선을 만들 수
있으므로, q를 더 정밀하게 재면 생성식을 식별할 수 없다. 반대로 같은 날짜의
실제 T,K가 최소 3개 이상 있으면 후보식은 그 값을 사후 조정하지 않고
검증할 수 있다.

따라서 다음 단계는 새 비율을 발명하는 것이 아니라, 기존 스크린샷에서
읽을 수 있는 숫자 눈금/커서 근거를 `anchor_observations` 원장에 고정하는
일이다. 원본 이미지가 공개 저장소에 없는 이유로 이 원장은 값이 검증될
때까지 빈 상태를 유지한다.
