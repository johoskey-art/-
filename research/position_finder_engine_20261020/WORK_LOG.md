## 2026-10-20 / 엔진 코어 v0와 화면 기하 사전분포

- `LeaderGate`와 `PositionBands`를 하나의 점수·수식으로 합치지 않았다.
  - `src/leader_gate_v0.py`: 가격구조·섹터 동행·EPS 상태·상투 후 위험을 투명 규칙으로 판정. 출력은 `confirmed/candidate/rejected/unknown`과 근거·결측이며 수익확률 점수가 아니다.
  - `src/position_finder_core.py`: 사후 역사 5/7 가격참조와 화면에서 관측한 named-band 상대배치를 분리 계산한다. 미래 고점은 실행입력이 아니다.
- 두 모듈의 단위테스트를 실행해 PASS를 확인했다. 로그축 q→가격범위의 하한/상한 역전 오류 1건을 테스트에서 발견·수정했다.
- 안정 화면 4개(PF001, PF009, PF012, PF018)의 12개 좌표에서 화면 q 사전분포 생성:
  - 어깨 0.200000 / 0.213203 / 0.234694
  - 허리 0.407609 / 0.426064 / 0.448980
  - 허벅지 0.711111 / 0.717172 / 0.724490
- 위 값은 `SCREEN_GEOMETRY_ONLY`이며, 차트별 로그축·가격단위 감사 전에는 가격 목표나 원작식으로 사용 금지.


## 2026-10-20 / 가격축 반증·엔진 수정

- 위치선 차트 **14개**(PF000–PF009, PF012, PF014, PF016, PF018)의 보이는 우측 가격 눈금을 감사했다. 모두 등간격 숫자축으로 렌더되어 `LINEAR_VERIFIED`로 기록했다: `results/chart_axis_audit_v0_20261020.csv`.
- 특히 초기 상대배치 사전분포의 원천 4개(PF001, PF009, PF012, PF018)도 선형축이다. 따라서 이전의 “화면 q를 로그가격 거리로 변환”하는 가정은 **반증**됐다.
- `src/position_finder_core.py`는 이제 `axis_scale`을 명시적으로 요구한다. 선형축은 `price = top + q × (knee - top)`, 로그축만 로그 보간을 쓴다. `unknown`은 UI에서 변환을 막는다.
- 로그 5/7 단계는 역사적 완결 사이클의 참조통계로 유지하되, 원본 HTS 위치선의 축 변환/원작 공식으로 해석하지 않는다.
- `app_position_finder_v0.py`와 데이터 번들을 저장소 안에 넣어 네트워크 없이 재현되도록 했다. 기존 38개 보정값은 `LEGACY38` 선택표본임을 화면에서 명시했다.
- 검산: 코어·LeaderGate 스크립트 테스트 PASS, 파이썬 컴파일 PASS. Streamlit 프로세스 기동은 시도했으나 이 실행환경의 localhost 접근 제약으로 브라우저 응답까지는 확인하지 못했다.
