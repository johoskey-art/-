# Chat / Work 분업과 한계 대응 — v0.8

## 목표

Chat의 실측 처리량보다 조사 범위가 큰 경우, 결과물을 위한 **증거 수집 단계만 Work로 분리**한다. 같은 100개 PDF를 단일 대화 컨텍스트에 우겨 넣거나, 30개만 처리했는데 100개를 모두 봤다고 말하지 않는다.

## 동작 방식

1. **작은 실제 파일럿**: Chat에서 상위 우선순위 자료 중 3~5개(여건에 따라 더 적게)를 대상으로 원문 읽기, 읽음 영수증, 원장 저장·재조회를 시험한다. PDF의 크기와 열람 제한에 맞춰 실제 작업 수량을 기록한다. 관측 능력이 없으면 고정 한도 수치를 추정하지 않는다.
2. **분업 판단**: 백로그와 실측 처리량을 비교하고, 서명·웹 사이트·이미지 중심 PDF 등 Work의 클라우드 브라우저/컴퓨터 조작이 유용한지 점검한다. Work는 별도 ChatGPT 모드이고 이 스킬이 저절로 시작하지 않는다.
3. **Work에 넘기는 경계**: 문서 발견→정보가치 후보 비교→원본 본문 섹션/표 확인→이벤트/기업 제품 주장 추출→고유 ID·출처 페이지·명확한 반론과 미확인점 기록→비공개 체크포인트 저장 및 재조회까지만 수행. 기업 최종 추천, EPS 주장의 확증 여부, HOME/EVENT 확정은 본래 스킬에서 독립 검토.
4. **Work 결과 확인**: 중복 PDF·원문이 아닌 전달 텍스트·본문 미열람·출처 위치 불명·상충 수치 혼동·저장 실패를 검사. Work가 만든 `READ_RECEIPTS`는 원본 ID·읽은 범위·근거 위치·구체적 주장과 주장의 증거 수준이 있어야 한다. `CLAIM_LEDGER`는 FACT vs ANALYST_INFERENCE vs HYPOTHESIS를 구분해야 한다.
5. **오류 발생**: Work 이용불가, 인증 필요, PDF 미열람, 체크포인트 저장 실패라면 남은 큐를 유지하고 Chat에서 작은 실행 단위로 계속. 실패를 성공 처리하지 않는다.

## 최소 인계 패킷 (private JSON)

- `industry`, `goal`, `master_reference`, `queue_reference`(존재하고 접근 가능할 때만), `scope`
- `work_scope`: 열어 볼 승인된 문서/사이트/폴더 및 **읽지 않은** 최우선 원본 목록
- `non_goals`: ETF/브로커 수입 포맷 임의 생성, 포트폴리오 변경, 검증되지 않은 고객관계 확정 금지
- `expected_outputs`: `CATALOG`, `READ_RECEIPTS`, `CLAIM_LEDGER`, `UNREAD_QUEUE`, `ERRORS`, `CHECKPOINT`
- `completion_criteria`: 이번에 실제 처리한 파일과 저장 검증을 증명. 처리 못한 원문은 남겨야 함

## Work용 안내 문장 (사용자에게 필요할 때만 제시)

> 전력기기 산업지도 조사 자료 수집을 이어서 수행해줘. 첨부한 인계 패킷의 미열람 우선순위 문서를 대상으로 원문 본문과 핵심 표·차트를 조사하고, 문서별 ID·읽은 섹션·페이지·새로운 EVENT/기업·반론·수치의 출처와 미검증점을 기록해. 중복 자료는 한 번만 보고, 비공개 저장 위치에 CATALOG/READ_RECEIPTS/CLAIM_LEDGER/UNREAD_QUEUE/ERRORS/CHECKPOINT를 저장한 후 다시 읽어 검증해. 최종 투자 종목 선정이나 확인되지 않은 EPS 추정은 확정하지 마. 처리하지 못한 자료는 미열람으로 남겨줘.

**주의:** 현재 Chat에서 Work 실행을 자동으로 호출하거나 진행상황을 실시간으로 조종하는 도구가 있다는 뜻이 아니다. 사용자가 ChatGPT에서 Work를 선택해 별도 작업을 시작해야 한다. Work에서 해당 플러그인 사용 가능 여부와 저장소 접근은 환경에 따라 다르며, 불가하면 입력 파일과 인계 패킷을 직접 제공한다.
