# 기존 Oracle→Google Drive Telegram 수집기를 우선 활용 — v1.0.1

## 이미 연결되어 있는 자료의 정체

사용자는 *새 Telegram 로그인/봇/스크래퍼를 요구하지 않는다*. 기존 Telegram 사용자 계정 수집기가 Oracle에서 실행되고 결과를 사용자 비공개 Google Drive `텔레그램 수집 자료` 아래에 누적한다. 이 프로젝트의 연결된 Drive를 먼저 살핀다. 본 문서는 **개인용 비공개 플러그인 지침**이며 Google Drive 폴더 식별자와 자료를 공개 GitHub·외부 검색·로그에 복제하지 않는다.

- 기준 폴더: `텔레그램 수집 자료`, Drive folder ID `<PRIVATE_DRIVE_FOLDER_ID>` (조회 전 권한 검증; 이것이 없는 세션에서는 폴더 이름으로 검색).
- `날짜별 텍스트/`: `YYYY-MM-DD.txt`, `YYYY-MM-DD_attachments.json`, `YYYY-MM-DD_attachments.html`. 문서별 날것 텍스트보다 JSON에 채널명/메시지ID/게시일/원문링크/첨부경로/상태가 구조화되어 있다.
- `원본 첨부/YYYY-MM-DD/<Telegram channel_id>/<message_id>.pdf|jpg...`: 실제 원본이 저장되었는지 날짜·채널 ID 폴더에 진입하여 파일을 검증.
- `외사 리포트/YYYY-MM-DD/`: 별도의 대외/해외 보고서 수집 자료.
- `OCR 텍스트/`: 일부 과거 날짜의 보조 OCR 자료; 모두 처리되었다고 가정하지 않는다.

2026-10-21 실제 connector 샘플에서 305개 메시지/20개 채널/105개 첨부(그중 PDF 2개), `2026-10-21.txt`와 동명 JSON이 확인되었다. **이 수치는 샘플 스모크 테스트만**이며 다른 날짜의 고정 수치나 전체 채널 수는 아니다. 오늘 원본 `ABB_3Q26_presentation.pdf`와 다른 실적자료 PDF가 실제 첨부 폴더에 있음을 확인했다. 저장만 되었다고 본문을 읽었다고 기록하지 않는다.

## 매 호출의 기본 조사 순서 (별도 사용자 명령이나 인증 요청 없이 가능한 범위)

1. 해당 Drive 폴더 `get_file_metadata/list_folder`로 접근 확인. 접속이 안 되면 `COLLECTOR_DRIVE_UNAVAILABLE` 명시하고 공개 리포트/현지어·기업 자료 조사로 진행. 처음부터 Telegram 계정 재로그인·새 봇 구축을 권하지 않는다.
2. `날짜별 텍스트`에서 최근 7일의 **실제 존재하는 날짜 파일**을 골라 서치한다. 과거 장기 이벤트·산업구조 테마라면 자료 발견이 부족한 제품 역할에 한해 30~90일 범위를 **선별 확장**한다. 수백 개 PDF를 한 번에 전부 읽지 않는다.
3. 파일명 검색만으로 멈추지 말고 **실제 본문 혹은 JSON을 읽는다**. 채널/저자 이름이 정해져 있다고 가정하지 말고, 산업→판매제품→기술/규격→국가→기업명을 다국어 키워드로 확장하며 누락기업과 새로운 원출처를 발견한다. JSON 파일은 읽기 인터페이스가 본문을 비우면 raw-file 스트림/실행 가능한 파일 처리 수단을 선택하고 **읽지 못했다고 표시**한다.
4. 메시지별 `channel`, `channel_id`, `message_id`, `date`, `text`, `link`, `grouped_id`, `kind`, `relative_path`, `status`, `sha256`를 인용 근거로 보존. `relative_path`가 있어도 `status=downloaded` 및 Drive 저장 확인 없이 첨부 열람 성공을 선언하지 않는다. 여러 채널이 같은 자료를 전달하면 원문 URL·내용 fingerprint·원 PDF로 하나의 소스 클러스터로 묶는다.
5. 수집기 포스트는 **발굴과 가설의 시작점**이지 그 안의 애널리스트 추정·고객 소문을 공식 실적/계약으로 확정하는 근거가 아니다. 원문 링크, 첨부 원 PDF의 실제 페이지를 읽어 중요 제품/기업/매출 비중을 뽑고, 고중요·고민감 주장만 DART/MOPS/EDINET/SEC/회사 IR로 교차 검증한다.
6. 결과물은 반드시 A(초등학생식 기술/밸류체인)→B(실제 제품·기업 피어·매출비중/기간/분모)→C(테마/EVENT→직접/2차·역효과)로 작성한다. 데이터 수집 일지는 보고서보다 앞에 오지 않는다.
7. 마무리에는 **검색한 날짜·파일·실제로 읽은 건수·중복 제거·비공개 첨부 접근 여부**만 간단하게 기록. `TXT와 JSON 색인 확인`/`PDF 첨부 존재 확인`/`PDF 본문 열람 확인`/`공식 공시 검증`은 서로 다른 단계다.

## 읽기 비용 / 연속성 한계

현재 ChatGPT에서 Google Drive 도구를 쓸 수 있는 세션이라면 별도 서버 증설 없이 파일을 읽을 수 있다. 그러나 30일×수백 메시지 전체를 매번 불러올 경우 모델 작업한도와 검색누락이 생긴다. 우선 기간별 메타+JSON에서 섹터 매칭 후보만 추출하며, 느려지면 **현 수집기의 저장 단계 옆에 추가 인덱서(sidecar)**만 붙여 주제·회사·원출처를 검색 가능하게 한다. 이때도 Oracle의 기존 Telegram 수집·인증은 건드리지 않는다. sidecar는 필수 선행조건이 아니다.

공개 GitHub에 텔레그램 원문·첨부·비공개 폴더 ID·로그인 자격증명을 절대로 업로드하지 않는다.
