# Industry Watchlist Builder

Produce a usable **industry and company comparison watchlist**, not a long research report. The watchlist is the final product. Do not re-create a previously validated map unless the evidence materially requires it.

## Operating modes

- **NEW**: no usable MASTER; discover the industry from scratch.
- **UPDATE**: load the latest MASTER, evidence register, scope, and change log; investigate only changed or uncertain claims.
- **AUDIT**: independently verify an existing map and produce a change set; preserve valid block order.
- **EXPORT**: generate broker-specific files from a verified MASTER, but only if the broker's exact accepted file syntax and instrument support were verified.
- **CORPUS START `<industry>` PRIORITY** (optional TARGET 100 ambition): start or resume a private, persisted research queue; catalogue domestic/foreign/Telegram/university/KIRS PDFs without confusing file discovery with reading.
- **CORPUS NEXT [N] PRIORITY [source]**: fetch the next N **different unread PDF reports** (default 10, tune to actual document size and available execution window), actually read their relevant body sections, charts/tables, risks, extract sourced claims, checkpoint the receipts, and keep going in future explicit turns. Never repeat a completed report just to fill a batch. Choose source filter as needed (TELEGRAM, UNIVERSITY, GLOBAL, PUBLIC, DRIVE).
- **CORPUS STATUS**: report actually-reviewed count, highest-information-value unread titles with reasons, uncovered roles/events, source/issuer diversity, and optional progress toward 100 ambition.
- **CORPUS FINALIZE**: never certify by PDF count alone; assess resolved coverage gaps, priority unread queue, independent policy facts, cross-sector negatives and diminishing information gain, else publish provisional work with explicit holds.

When files or broker templates are not accessible, issue an explicit `UNVERIFIED` record and produce a broker-neutral preview instead. Never invent an import format or claim an account was updated.

## ChatGPT tool orchestration

- Use the user-connected Google Drive connector for private report discovery and reads; public web research for global primary/company/industry sources. A skill never grants access itself.
- If the user requests GitHub persistence and the connector is connected with write rights, preserve source provenance and write only after verifying the destination repository; do not put private report full text or personal holdings into a public repository without clear authorization.
- For a phone-first conversation, prioritize in-chat HOME/EVENT summaries and link to verified generated files; do not pretend the mobile host can execute bundled Python scripts.
- If broker formats or connected broker account actions are unavailable, use broker-neutral text and hold broker-specific imports, rather than fabricating success.

## Mandatory execution sequence (v0.5)

1. **Load & scope-lock**. Read existing MASTER and latest confirmed watchlist, prior decisions, test cases, and user-specified included/excluded products. Freeze scope for the run. Respect user exclusion rules regardless of report coverage.
2. **Report-corpus first: archived + current + diversified source types**. Before closing any HOME or EVENT, query the connected Drive **across historical dates, brokerage houses and neighboring sectors** (e.g. power equipment + solar inverter + ESS + battery/BBU + AIDC + geopolitics/policy), alongside international research, sector publications and leader IR. Use two-pass ingestion: list/catalog **all plausible reports and their dates/issuers first**, then **rank prospective PDF reviews by expected marginal information and fill material coverage gaps across resumable batches**. Aim for a rich corpus (100 unique PDFs if valuable) but do not force redundant reports or use count to decide completeness. Scan/metadata never count as read; every counted report has a source locator, read sections, 2+ extracted findings, and a dated receipt. Deep-read high-novelty items fully; log targeted body-reading honestly (do not label it full-text). Prioritize genuinely different analysis/contradictions and do not count duplicate forwarded PDFs. Preserve source IDs, duplicates, search queries, date range, exclusions, unread/unavailable files and work remaining in `report_corpus_audit`. A single PDF-reading batch does not finish historical-event discovery. Do not infer reading completion from a large catalog. Read `references/report-corpus.md`, `references/source-diversity.md`, and `references/discovery.md`. Show actual reviewed count versus research ambition separately from a coverage-quality verdict; persist queue to a user-authorized private store and verify read-back.
3. **Historical EVENT discovery and cross-sector retrieval**. Build/refresh a persistent canonical `event_registry` *before selecting current events*, using old broker reports, current broker reports, primary laws/regulations, customer/competitor IR and prior MASTER. De-duplicate reports by same underlying event and primary source, but retain their differentiated investment claims and contradictions. For policy events, verify **official legal ID, enacted vs proposed status, precise product scope, national-origin/control conditions, applicability, exceptions and effective dates**. An analyst report repeated by many houses does not override the controlling primary source. Distinguish event first occurrence vs newer thesis/evidence. Retrieve EV/ESS/PCS/BBU/inverter/transformer topics across sectors, not merely `전력기기` titles. Record event hypotheses and negative cases even if not yet in HOME. Read `references/event-research.md` and `references/events.md`.
4. **Coverage audit & company discovery**. Draw a provisional product/role value chain before finalizing companies. For **every existing and new product HOME**, log four mandatory research tracks: (a) global leaders/direct peers, (b) domestic small/mid-cap specialists, (c) foreign smaller/niche specialists, (d) existing-company cross-product and subsidiary/sales/contract exposure. Search by function, installation point, local industry terminology, competitors, order announcements, customer/industry sources and official IR. Do **not** stop just because two or three famous firms explain a role. Do not rely on analyst coverage or market cap as a discovery gate. Record included, excluded and held candidates with reasoning and evidence in `coverage_audits` and `candidates`. Read `references/discovery.md`.
5. **Verify company × product × business mode**. Check each discovered firm's *other sellable products* and subsidiaries in reverse, not just the product used to find it. Distinguish manufacturer vs supplier/distributor/integrator, contracting entity vs producer, and sales agreement/framework amount vs recognized revenue. Multiple HOME entries are allowed **where an economically material documented role exists**; if not verified, log a candidate HOLD rather than assume exclusion. Capture product-specific `claim_specifics`, `business_mode`, `business_stage`, `profit_mechanism`, dated evidence and product-level role. Identify cap/liquidity/market beta separately from segment earnings sensitivity; never fabricate event-beta calculations. Read `references/evidence.md`.
6. **Build HOME and nearest-peer blocks**. Group chiefly by WHERE+WHAT and SAME MONEY DRIVER. Distinguish direct competitors from financially relevant suppliers/channels and label product role explicitly. Preserve stable HOME order and global reference positions; **do not limit stock coverage to 2–6 large firms** (that is a visual heuristic, not a discovery limit). Additional specialists with distinct earnings exposure are welcome with defensible evidence. Maintain all candidate decisions and new cross-product memberships. Read `references/peer-and-order.md`.
7. **Construct selective EVENT transmission from the registry**. For each discovered material event and scenario, calculate/qualitatively trace direct, upstream, downstream, alternative, competitor and excluded-firm outcomes into Q/P/MIX/SHARE/UTIL/COST/YIELD -> margin/EPS/FCF. Tag whether exposure is CONFIRMED, CONDITIONAL, INFERRED or NOT EXPOSED and specify what would change that rating. Separate regulatory product inclusion from manufacturer origin and actual profit sensitivity; do not silently assume a rack BBU is a grid UPS. Include first occurrence, later report consensus/dissent, catalysts, rebuttals and timeline. Only high-sensitivity companies go in final EVENT display but preserve rejected hypotheses in registry. Read `references/events.md` and `references/event-research.md`.
8. **Independent quality gate**. Apply `references/verification.md` including **role-level coverage**, logged small/mid-cap and overseas search, incumbent cross-product audits, **historical/multi-broker/cross-sector report audit**, **canonical event registry**, differences/independence of cited analyst theses, primary-law cross-checks, included/held/excluded candidate decisions, meaningful non-placeholder product evidence, order vs recognized revenue and all prior unresolved holds. A superficially neat map or script `0 errors` does **not** certify no omitted firms. The audit must explicitly list uncovered groups and unknown EPS sensitivity; a missing search is a HOLD, not a `NO_MATCH_FOUND`. With Python, run `python scripts/validate_master.py audit <master.json>` and `python scripts/validate_master.py validate <master.json> --strict` (strict nonzero is expected if holds remain). Without Python, manually run the equivalent gate and state `AUTOMATED_VALIDATOR_NOT_RUN`. Reopen only affected steps and maintain earlier errors as regression cases.
9. **Render and export**. When execution is available, run `python scripts/validate_master.py render <master.json>`; otherwise create the same company-first preview. HOME value-chain sequence and EVENT earnings transmission sequence are separate. Do not suppress high-sensitivity small companies simply to meet a 2–6-firm layout target. Print a compact **coverage/QA summary** including unperformed search tracks, unread report/date/sector clusters, canonical EVENT coverage and unresolved legal disagreements, held/excluded candidates, unsupported product modes and broker holds. Confirm exact broker import format before outputting broker-specific file. Read `references/export.md`.

## Evidence-first document prioritization and resumed investigation — v0.5

- An industry marked **COMPREHENSIVELY_RESEARCHED** requires **role/event/contradiction/earnings coverage passed and highest-value unread hypotheses reviewed** over current and prior verifiable runs. The 100-PDF target is an optional broad research ambition, NEVER the definition of completeness. **No arbitrary quota per run**: choose the batch that fits real content and context; user can run `CORPUS NEXT 10`, `CORPUS NEXT 20`, or another count repeatedly. A request for NEXT means advance the cursor, not summarize old files again. Do not claim asynchronous or unscheduled processing.
- Reading proof per PDF: stable ID/link, issuer and report date, `PDF_REPORT`, reading level (`BODY_REVIEWED` or `DEEP_READ`), 2+ substantive sections, 2+ sourced novel claims/observations, section/page/table locators, reader and date. **Title skim, metadata, Telegram summary or abstract-only preview is not PDF body-reading**. Count identical report editions/forwards only once; different versions count if meaningful analytical changes exist and are logged.
- A 100-report **research ambition does not license junk sources**. Search all relevant source families: user's Google Drive archive, external public industry & brokerage research, official government/industry bodies and global IR, accessible Telegram collector exports and saved original attachment PDFs, KUVIC/SMIC/S.T.A.R/other university teams, and Korea IR Council/KIRS and independent deep-dive studies. University/team reports are valuable for role discovery, diagrams, technical explanations and hypotheses, but their margins, valuation, TAM, sales estimates, and alleged contracts require independent official-source confirmation. Telegram forwards are leads, not independent confirmations.
- Keep **private cumulative queue + reading ledger + event registry**, with de-duplication and last processed IDs. Checkpoint and read back after EACH run. If private persistence cannot be confirmed, output a portable JSON checkpoint for the user to reattach; explicitly mark NEXT as blocked without accessible state. Never upload full licensed broker text or private collector exports into public GitHub.
- Never force low-value redundant documents to reach 100. Report counts transparently but judge the result from remaining material industry roles, events, alternative theses, missing EPS links, and independent evidence. Do not close research when high-impact unread reports or critical coverage gaps remain, even if 100 PDFs were read.

## Next-best-report selection — mandatory (v0.5)

- **The next 10 reports matter more than an arbitrary total 100.** Read `references/reading-priority.md`. Before opening full PDF bodies, build a wide bilingual/multi-source catalogue and a coverage matrix of missing product roles, policy/industry EVENTS (including historical origins), company earnings drivers, countries, contrary arguments and under-covered small caps.
- **Selection uses information gain per unit of reading effort**, not issuer prestige, report publication date or sheer report count. Prioritize novel important facts, missing-coverage closure, differentiated estimates, company×product EPS links, contradictions, and primary-source traceability. Penalize repetitions of the *same underlying thesis*, including different broker reports copying one policy release. Preserve dissent and updates.
- **Source roles differ:** KUVIC, SMIC, S.T.A.R., KIRS, international specialist reports and Telegram-collected originals may outrank large-broker outlooks on industrial microstructure. Use verified official source documents for laws/contracts/quantities and distinguish student or analyst hypotheses.
- After **each batch**, recompute priority based on events/companies/products newly learned; skip the next report if it merely repeats what is now known. Maintain an auditable candidate score with a `priority_reason`, possible new role/event tags, assessed uncertainties, and unread top-priority titles. Metadata estimates are not facts about unread PDFs.
- **Stop by marginal insight and gap coverage, not quota:** allow early conclusion only with documented search across all material role/event dimensions, resolved highest-priority candidate reads, reviewed major conflicting theses, no material critical holes, and a source-linked `research_decision` assessing last batches. Hitting 100 without these checks is NOT completion. A justified smaller corpus can produce a high-quality map but must state its reviewed count and remaining limitations.
- `CORPUS START 전력기기 PRIORITY`, `CORPUS NEXT 20 PRIORITY`, `CORPUS RERANK`, `CORPUS STATUS`, and `CORPUS FINALIZE` are natural-language intents. `NEXT` advances to unread highest-marginal-value material; `RERANK` recomputes after discoveries. Don't claim these are independent shell commands or that work runs in background.

## EVENT research completion gate — mandatory

- **Do not close EVENT research solely from recent reports**. Enumerate date/sector/source coverage (recent + material historic catalysts) and save a resumable cursor when PDFs cannot all be read in one run. Search summaries before deep-reading; de-duplicate only repeated facts, not dissenting investment interpretations.
- Each major EVENT must have a stable canonical ID, first_seen, historical source provenance, authoritative primary document (or `PRIMARY_UNVERIFIED`), at least one genuinely different interpretation/negative case, product-scope and implementation-stage checklist, and an economic link to actual company×product businesses. Mark unavailable evidence HOLD; do not invent it.
- **Unknown event coverage must be reported as a HOLD**; a clean HOME map and structural validator pass cannot certify there are no missing events. An empty registry is not evidence of no catalysts; report unsearched eras/domains explicitly.
- For laws, do not upgrade national-origin exclusion to blanket ban or conflate inverter/utility BESS/critical UPS with rack-level BBU. If archival sell-side titles or cited legal IDs contradict official laws, correct the canonical ID and retain original assertions as source errors.

## Core decisions and stopping conditions

- No new group merely for an interesting material, process, theme, or customer; create a distinct economic block only when product/customer, ASP, margin, scarcity, qualification, or earnings sensitivity differ meaningfully.
- A **structurally important** company with weak direct EPS exposure can still be an essential industry-map or signal reference; distinguish CORE / STRUCTURAL / OPTION / SIGNAL at **company-product** level.
- A missing role is material if excluding it hides a major buying decision, integrator, substitute, bottleneck, or causal link. Search until such gaps have defensible representatives and additional candidates add little incremental understanding; log unresolved gaps.
- Prefer company/filing/IR for *what a firm actually sells*, independently triangulate for *market share, technical superiority, rival position and supply-chain relationships*. Newer verified operating data override older outlook, without erasing useful older mechanism/history.
- Never infer exact buyer–supplier relationships from a value-chain arrow without supporting evidence.
- Stop when essential product roles, global leaders, domestic small/mid-cap peer search, overseas specialist search, cross-product business review, candidate decisions, economic differences and negative cases are **documented as checked or explicitly held**. No fixed target company count, but an unsearched category never satisfies the stop condition.
- Output must distinguish `VERIFIED`, `ESTIMATED`, `OPTION`, and `HOLD`. Do not silently upgrade unsupported statements.

## Final deliverables

1. `MASTER` v0.3 with company × product × business mode, product-level evidence, cross-HOME assignments, role-coverage research trails, candidate inclusion/hold/exclusion decisions and status.
2. `report_corpus_audit` + `report_queue` (with ranked information-value reading ledger) + `event_registry` with a deduplicated evidence lineage, broker consensus/dissent and explicit unknowns; plus `HOME` and `EVENT` company-first preview.
3. `CHANGELOG` showing additions, removals, group moves, source and cause.
4. `QA` report showing **both structural errors and missing discovery work** (including unanswered small/mid-cap, overseas, cross-product or broker checks); broker-specific export **only after actual import format confirmation**.

A bundled Python validator **checks data structure, not market facts or omitted firms**. A full discovery audit requires actual searches and independent source review. The skill orchestrates available access/tools; it does not grant new Google Drive, securities account, or exchange entitlements. When a source or tool is unavailable, continue with admissible evidence and document the gap.
